# Decisions

Why things are the way they are. Append only. One entry, one to three lines. Add one when you choose something a later reader might otherwise undo.

- **Aliases are plain `lct serve` argument strings, expanded before Click parses.** (2026-09-24) One concept, no schema. Options typed after an alias win because Click keeps the last value; `--extra-args` is replaced whole, not merged.
- **Aliases live in `aliases.toml` in the cache dir (`tmp/` in a checkout).** (2026-09-24) It is user data, so it follows the `cache.py` rule and is gitignored. Saving from the TUI rewrites the file and drops comments.
- **The TUI is Python + Textual, not Go/Rust/TypeScript.** (2026-09-24) It calls lct's own functions and CLI, so no logic is duplicated and there is one toolchain. Textual gives tabs, tables, selects and async logs out of the box.
- **The TUI runs `lct serve` / `lct pull` as child processes and `llama-bench` directly.** (2026-09-24) Reuses CLI resolution and signal handling. Children get their own session and are stopped with SIGINT to the group, which is what Ctrl-C does.
- **Benchmarks use `llama-bench`, never custom timing code.** (2026-09-24) A custom benchmark was removed in `816ef60`; llama.cpp's tool is the reference.
- **Default context limits come from measured VRAM on the 7900 XTX (24 GB).** (2026-09-24) Qwen3.8-27B Q4_K_M: 128k with the projector, 160k text-only, using `-ub 1024` and q8_0 KV for the MTP draft (`-ctkd/-ctvd`). 180k text-only leaves ~0.35 GB and is too tight.
- **The TUI copies forseti's look: text and keys, not widgets.** (2026-09-25) The first version used Textual's boxed inputs, selects and buttons and read as generic. Now: near-black theme, one indigo accent, colour only for status, a key-hint line, OptionLists and one-line inputs. Serve acts on saved profiles, so a server always starts from a named, reproducible command.
- **Profile edits autosave; untouched model and projector fields keep their original tokens.** (2026-09-25) So editing the context of a repo-based profile does not rewrite it as a local path or drop its auto-selected projector.
- **Colour carries meaning, but more than status.** (2026-09-25) Numbers teal, images and likes pink, running and downloaded green, warnings amber, headings and keys indigo. White-and-indigo only read as colourless.
- **Settings are text rows edited one at a time, not a column of inputs.** (2026-09-25) Standing inputs looked heavy, captured page keys and made `tab` walk every field. A single edit line opens on `enter`; `tab` only switches panes; nothing takes focus unless you ask.
- **Anything that starts work needs a deliberate key.** (2026-09-25) A click only highlights; `enter` or a double-click acts; downloads also ask `y`. Stray clicks were starting servers and multi-GB downloads.
- **The TUI uses Kanagawa Dragon, replacing the indigo palette.** (2026-09-26) Matches the user's nvim and terminal. Colour roles stay the same; only the hex values in `tui.py` changed. Selection is Kanagawa's `#2d4f67`, not an accent tint, which read as grey.
- **The TUI's server outlives the UI.** (2026-09-26) It is spawned in its own session writing to `server.log`, not a pipe; its name and pid go in `server.json`. A new `lct tui` replays the log and can stop it. A stale pid reused by another process is not guarded against.
- **Servers are tracked per profile in `servers/<name>.json` and `.log`, replacing `server.json`.** (2026-09-28) One mechanism for `lct up` and the TUI, so either can stop what the other started. Stacks are a `[stacks]` table in `aliases.toml`, not a new file.
- **Background LLM jobs run on a CPU side model, not the GPU model.** (2026-09-28) The GPU server has one slot; a 957-token title request evicted an 18k chat prompt and cost a 22 s re-prefill. CPU prefill is ~150 t/s, so the side lane only suits short prompts; commit messages stay on cloud Haiku.
- **No n-gram drafting on Swift-Qwen3.8-27B.** (2026-09-28) MTP alone already accepts 655/656 drafts on a copy-heavy edit (120 t/s); adding `ngram-mod` (n 3–12) dropped it to 105 t/s. Prose unchanged at ~60 t/s.
- **`swift-qwen` runs 112k, `-np 2 --kv-unified`, `-ub 512`, `--no-cache-idle-slots -cms 2048`, `--env GGML_VK_SUBALLOCATION_BLOCK_SIZE=4294967296`.** (2026-09-28) Two GPU device-lost crashes: at 150k and again at 128k with a 125k-token prompt, prefill fell to ~57 t/s at depth 110k and a GPU job passed the amdgpu watchdog. llama.cpp #27734 (same card/model): 1 GiB Vulkan suballocation blocks fragment the KV pool near 131k. 112k leaves 1.7 GB free for the projector.
- **The TUI uses thin rounded panels with titles in the border, bar meters and key caps.** (2026-09-28) The user asked for a premium, professional look. This replaces "no boxes" for page sections only; inputs stay one-line and borderless, and colour roles are unchanged.
- **`lct serve --env NAME=VALUE` passes environment to llama-server.** (2026-09-28) Backend tuning variables belong in the profile next to the flags, so a server started from the TUI or `lct up` is reproducible.
- **`--no-cache-idle-slots` with `--kv-unified`.** (2026-09-28) Its default clears every idle slot to the RAM cache when any request starts, so each classifier call wiped the chat's slot and the next turn reread 60k+ tokens (110 of 121 requests fell back to LRU). Off, the chat keeps its slot (reads ~150 new tokens). `-cms 2048` bounds the rollback after an interrupted reply on this hybrid model.
