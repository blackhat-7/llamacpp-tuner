# Decisions

Why things are the way they are. Append only. One entry, one to three lines. Add one when you choose something a later reader might otherwise undo.

- **Aliases are plain `lct serve` argument strings, expanded before Click parses.** (2026-09-24) One concept, no schema. Options typed after an alias win because Click keeps the last value; `--extra-args` is replaced whole, not merged.
- **Aliases live in `aliases.toml` in the cache dir (`tmp/` in a checkout).** (2026-09-24) It is user data, so it follows the `cache.py` rule and is gitignored. Saving from the TUI rewrites the file and drops comments.
- **The TUI is Python + Textual, not Go/Rust/TypeScript.** (2026-09-24) It calls lct's own functions and CLI, so no logic is duplicated and there is one toolchain. Textual gives tabs, tables, selects and async logs out of the box.
- **The TUI runs `lct serve` / `lct pull` as child processes and `llama-bench` directly.** (2026-09-24) Reuses CLI resolution and signal handling. Children get their own session and are stopped with SIGINT to the group, which is what Ctrl-C does.
- **Benchmarks use `llama-bench`, never custom timing code.** (2026-09-24) A custom benchmark was removed in `816ef60`; llama.cpp's tool is the reference.
- **Default context limits come from measured VRAM on the 7900 XTX (24 GB).** (2026-09-24) Qwen3.8-27B Q4_K_M: 128k with the projector, 160k text-only, using `-ub 1024` and q8_0 KV for the MTP draft (`-ctkd/-ctvd`). 180k text-only leaves ~0.35 GB and is too tight.
- **The TUI copies forseti's look: text and keys, not widgets.** (2026-09-25) The first version used Textual's boxed inputs, selects and buttons and read as generic. Now: near-black theme, one indigo accent, colour only for status, a key-hint line, OptionLists and one-line inputs. Serve acts on saved profiles, so a server always starts from a named, reproducible command.
- **Profile edits autosave; untouched model and projector fields keep their original tokens.** (2026-09-25) So editing the context of a repo-based profile does not rewrite it as a local path or drop its auto-selected projector.
- **Colour carries meaning, but more than status.** (2026-09-25) Numbers teal, images and likes pink, running and downloaded green, warnings amber, headings and keys indigo. White-and-indigo only read as colourless.
- **Settings are text rows edited one at a time, not a column of inputs.** (2026-09-25) Standing inputs looked heavy, captured page keys and made `tab` walk every field. A single edit line opens on `enter`; `tab` only switches panes; nothing takes focus unless you ask.
- **Anything that starts work needs a deliberate key.** (2026-09-25) A click only highlights; `enter` or a double-click acts; downloads also ask `y`. Stray clicks were starting servers and multi-GB downloads.
- **The TUI uses Kanagawa Dragon, replacing the indigo palette.** (2026-09-26) Matches the user's nvim and terminal. Colour roles stay the same; only the hex values in `tui.py` changed. Selection is Kanagawa's `#2d4f67`, not an accent tint, which read as grey.
- **The TUI's server outlives the UI.** (2026-09-26) It is spawned in its own session writing to `server.log`, not a pipe; its name and pid go in `server.json`. A new `lct tui` replays the log and can stop it. A stale pid reused by another process is not guarded against.
- **Servers are tracked per profile in `servers/<name>.json` and `.log`, replacing `server.json`.** (2026-09-28) One mechanism for `lct up` and the TUI, so either can stop what the other started. Stacks are a `[stacks]` table in `aliases.toml`, not a new file.
- **Background LLM jobs run on a CPU side model, not the GPU model.** (2026-09-28) The GPU server has one slot; a 957-token title request evicted an 18k chat prompt and cost a 22 s re-prefill. CPU prefill is ~150 t/s, so the side lane only suits short prompts; commit messages stay on cloud Haiku.
- **No n-gram drafting on Swift-Qwen3.8-27B.** (2026-09-28) MTP alone already accepts 655/656 drafts on a copy-heavy edit (120 t/s); adding `ngram-mod` (n 3–12) dropped it to 105 t/s. Prose unchanged at ~60 t/s.
- **`swift-qwen` runs 112k, `-np 2 --kv-unified`, `-ub 512`, `--no-cache-idle-slots -cms 2048`, `--env GGML_VK_SUBALLOCATION_BLOCK_SIZE=4294967296`.** (2026-09-28) Two GPU device-lost crashes: at 150k and again at 128k with a 125k-token prompt, prefill fell to ~57 t/s at depth 110k and a GPU job passed the amdgpu watchdog. llama.cpp #27734 (same card/model): 1 GiB Vulkan suballocation blocks fragment the KV pool near 131k. 112k leaves 1.7 GB free for the projector.
- **The TUI uses thin rounded panels with titles in the border, bar meters and key caps.** (2026-09-28) The user asked for a premium, professional look. This replaces "no boxes" for page sections only; inputs stay one-line and borderless, and colour roles are unchanged.
- **`lct serve --env NAME=VALUE` passes environment to llama-server.** (2026-09-28) Backend tuning variables belong in the profile next to the flags, so a server started from the TUI or `lct up` is reproducible.
- **`--no-cache-idle-slots` with `--kv-unified`.** (2026-09-28) Its default clears every idle slot to the RAM cache when any request starts, so each classifier call wiped the chat's slot and the next turn reread 60k+ tokens (110 of 121 requests fell back to LRU). Off, the chat keeps its slot (reads ~150 new tokens). `-cms 2048` bounds the rollback after an interrupted reply on this hybrid model.
- **Jeeves runs on its own PyTorch server, not llama.cpp.** (2026-10-01) Its answers come from a pointer head and diffusion drafter llama.cpp cannot run. One `--backend` option on `setup`/`serve` keeps profiles, stacks and the TUI unchanged; its venv lives in the cache dir so lct does not depend on torch.
- **Jeeves on the 7900 XTX uses `--precision fp8`.** (2026-10-01) bf16 (17.9 GB + 3.1 GB drafter) runs out of 24 GB while loading. fp8 works on ROCm (Triton w8a16 kernel) at 15 GB VRAM.
- **`swarm` uses UD-IQ4_NL, not UD-Q4_K_S.** (2026-10-02) Pi compacts at context − 16k, so agents need 64k each. Q4_K_S (21.4 GB) only fit 5 × 26k; IQ4_NL (18.5 GB) fits 5 × 64k at 23.0 GB VRAM. Nothing better fit this week (Reddit scan).
- **Strata runs from its own folder; lct only starts its run config.** (2026-10-03) Strata's `./setup.sh` compiles the engine and repacks the model; lct would only duplicate that. Profile `strata-flash-next` serves Flash-Next IQ3_S on 127.0.0.1:8080, in no stack. Measured 56 t/s prose, 67 code, ~50 at 117k, ~840 t/s prefill vs ~20 t/s for Q4_K_XL on llama.cpp.
- **`lct setup` downloads llama.cpp's prebuilt release for the detected GPU.** (2026-10-03) A friend's Vulkan build died on a missing `SPIRV-Headers`. `nvidia-smi` → CUDA 12.8 build plus the release's `cudart` tarball in one folder (RUNPATH `$ORIGIN`; driver supplies `libcuda`); else Vulkan; macOS Metal. Only `--cmake-arg` builds from source.
- **Speed work must not lower quality.** (2026-10-10) The user wants quality equal or better. Speculative decoding and kernel/VRAM work are fine; weights below Q4_K_S and KV below q8_0 are not. So 3-bit GSQ-RCO and 4-bit KV, which would reach 262k, are ruled out (`docs/qwen27b-speed-research.md`).
- **`swift-qwen` drafts with DFlash2 (n 5) at 96k, replacing MTP n 4 at 112k.** (2026-10-10) Thinking on: 82 / 92 t/s prose / code vs 72.5 / 77; no thinking: 59.8 / 129 vs 57.9 / 104. Greedy output identical, so lossless. The drafter needs ~1.1 GB more VRAM; the user chose 96k over 88k. Projector on CPU fits 112k but an image took 86 s vs 6.6 s.
- **Rejected for the 27B (2026-10-10):** Vulkan PR #25666 (no change), DSpark v2 (42.8 / 84 t/s, below MTP), n-gram before DFlash2 (code edits slower), DFlash2 n 7 (prose −11%), confidence cutoffs `--spec-draft-p-min` (code +6%, prose worse), q4_0 draft KV (frees nothing).
- **Flash-Next stays on IQ3_XXS, not IQ3_S.** (2026-10-11) Pi replayed 5 of the user's past tasks (8 slots, hidden checks, sandboxed): both passed 5/8, but IQ3_S took 104 min vs 66 and needs 57 GiB RAM vs 45. Harness: `tmp/ab-eval` (gitignored).
- **Flash-Next on Strata stays the long-task model; no better model fits.** (2026-10-12) A 105-agent web study found none that beats it for agentic coding at ≥3 bits in 24 GB VRAM + ~80 GB RAM; GLM-5.3-Flash leads by ~2 points but needs ~120 GB. Details: `docs/flash-next-speed-research.md`.
- **Tuned Strata goes in a new run config, `strata-swift-iq3_xxs-tuned.json`, not over the user's.** (2026-10-12) `--pcie-frac 0.35 --pcie-mode dma --ple-io ram --pool-workers 6` + the hipBLASLt 100202 table + fused prompt kernels: prompts 2.2×, decode +3–8%. 6 workers trade ~3% for half the CPU heat. The VRAM reserve (1500 = +12%) is the user's call.
- **Strata loads a patched ROCr from `~/rocm/rocr-7.2.4-fix`.** (2026-10-12) hsa-rocr 7.2.4's `BlitSdma::PendingBytes` reads one slot past its ring table; Arch's `_GLIBCXX_ASSERTIONS` turns that into the "~1 in 90" Strata abort. Reproduced without Strata; one-line fix in `tmp/strata-tuning/rocr-fix/`.
- **Rejected for Strata on gfx1100 (2026-10-12):** gfx1151's exact switch table (flat; three switches slower), the ROCm 7.14.1 SDK (prompts −21%), HIP launch env knobs, a short pool spin (−22%), faster adaptive swaps, `--prefill auto:32768`.
- **CPU power limit PL1 75 W / PL2 125 W, not more cooling.** (2026-10-12) The user chose it after Strata + an agent test suite hit 99 °C at 95/181 W. A oneshot service `cpuPowerLimit` in the system-manager config (`~/dotfiles/nix/linux`) sets it each boot.
- **Strata gets a Swift-1.5 expert profile, not the shipped base-model one.** (2026-10-13) The shipped ranking held 51% of Swift's routed experts at reserve 4000; one built from 18 Swift routing traces holds 68% held-out (code), +37% decode cold. Prose drops 6 points cold; the adaptive tier recovers it.
- **13 pool workers again, now that the CPU is capped at 75/125 W.** (2026-10-13) The cap limits heat on its own (83 C max over a minute of decode); 6 workers cost 10% on code and 18% on edits.
- **Strata runs 0.1.43 with `STRATA_ADAPT_LAG=2`.** (2026-10-13) 0.1.43 adds env node cuts (+4% code, bit-exact) and an RX 7000 image-crash fix. Without the lag, the adaptive tier's copy stall dropped prose to ~66 t/s with the Swift profile; with it prose is 81, code 110.
- **The user's Strata runs a locally built engine from branch `opt/combined`, not the stock 0.1.43 binary.** (2026-10-14) Six gfx1100-only decode changes, each bit-exact and switchable off; +16% code, +15% prose, +6% edit vs stock. The binary lives in `Strata-data/engines/` so `./update.sh` cannot overwrite it; revert by pointing `exe` back to `Strata/engine/strata`.
- **Strata round 4 settings: matrix-core prompt path, 16K chunks, reserve 2000, agent draft vocabulary, `--mtp-window 8192`.** (2026-10-14) Prompts +45%, live decode +12-19%. The prompt switches round like `STRATA_PF_GEMM` (1 flipped prediction in 95 windows, as a cache-size change); the rest are lossless. 2000, not 1500: the user keeps both monitors on this GPU and 1500 leaves the desktop 0.3 GB.
- **The engine reads a prompt chunk's PLE rows with pread on 16 threads; no `MADV_RANDOM`, no extra page-cache drops.** (2026-10-14) An evicted table cost a 15K prompt 15.8 s on one thread (now 1.3 s). `MADV_RANDOM` got the table's pages reclaimed first (decode +5.5 ms a round); 64 threads and dropping the expert load's cached copy measured no gain.
- **Strata saves its learned expert profile at the first request 5+ minutes after the last save (`expert_profile_save`), not on exit.** (2026-10-14) A session's cache hits climb from ~75% to ~87% as it adapts; starting from the saved profile skips that. `lct down` signals the whole process group (llama-server needs SIGINT), which kills the engine before its save-on-exit, so the timer does the saving.
- **`--ple-io mmap` plus row prefetch, not `ram` or `direct`.** (2026-10-14) With `side` holding 18 GB the 27 GB PLE table cannot stay in RAM: `ram` re-touched it for ~50 s at each start and still faulted rows one at a time (prose 21-85 t/s); `direct` waited on slow SSD reads. `MADV_WILLNEED` prefetch + mmap: code 131, prose 96, edit 118 t/s with the stack up.
- **`bench/strata-compare` (the cross-machine Strata profile) and `share/` (our expert profile and draft vocabulary) live on `main`; benchmark results stay on branch `strata-5090-compare`.** (2026-10-14) Other lct users get the tool and settings with a normal pull; per-machine logs do not clutter `main`.
- **Strata round 6: engine `ce0f1ae8` (v_perm i-quant signs, upstream batched commit, cumulative-acceptance draft stop) and the CPU pool's share of short prompt chunks.** (2026-10-15) Decode +3-5% on code and edits, +1-3% on prose; 0.8-3.6K prompts 19-34% faster. The engine changes are bit-exact; the draft stop and the CPU share are rounding-level (greedy flips at near-ties), within the lossless-or-rounding rule.
- **No PM4 graph replay on this GPU.** (2026-10-15) It gave +6-10% decode, bit-identical, but page-faulted the GPU 3 times in ~14 runs; each fault reset the whole GPU (VRAM lost, Hyprland crashed once). Revisit only with a fix, a long soak and the user's OK, since it drives the desktop.
- **No faster CPU expert kernels at `--pcie-frac 0.35`.** (2026-10-15) The pool and the PCIe DMA read DDR5 together (~70 of 76.8 GB/s); a pool 8-11% faster made the GPU wait longer for its DMA and decode fell 1%.
- **Strata round 7: engine `210ebbdd` (one-kernel HC read, fewer graph nodes, attention and GEMV kernels) + Basalt's MTP dense with re-rounded Q2_0 experts.** (2026-10-16) Decode +10-17% in a same-text A/B; main-model windows bit-identical, the drafter flips near-ties (prose 12/600). Left out `STRATA_HEAD_MIX_MULTI`/`_HEAD_Q8` (head not bitwise, 0.04 ms); gr_one stays on (bounded in-kernel waits; a timeout stops the server; `STRATA_GR_ONE=0` costs ~2%).
- **Strata round 8's expert-path node folds stay off.** (2026-10-16) `STRATA_GU_SWIGLU`/`_DOWN_WAITB`/`_DOWN_WAITA` (branch `opt8/launch`) cut 192 nodes a window bit-exactly but measured code +1%, prose and edit -1% (noise): those nodes run while the GPU waits for the CPU experts. Three new in-kernel sync points for no net gain; cut critical-path nodes instead.
- **Strata round 9's launch cuts stay off.** (2026-10-17) `STRATA_QSA_NR3` + `STRATA_Z_CONVAB` (branch `opt9/critical`) are bit-exact and cut GPU time 0.17-0.20 ms a round (~0.8%), within t/s noise. Node cuts are spent; the next lever is drafter acceptance (self-distillation).
- **A profile picks its own llama-server with `serve --server PATH`.** (2026-10-17) H2O-Lightning-4B needs an unmerged llama.cpp PR; swapping the managed build would move every profile onto a PR branch. Drop the option's use once the PR is in a release.
- **Classification goes to Flash-Next; H2O-Lightning-4B only on the GPU for bulk; Jeeves retired.** (2026-10-17) H2O on the CPU took 4-7 s an item and slowed Strata 5-15%; Flash-Next answers a short item in ~0.5-1 s with thinking off and reasons better. H2O's edge is calibrated probabilities at ~0.1 s an item, worth stopping Flash-Next only for big jobs.
- **Strata round 9b: self-distilled drafter `rt-sd2-swift` with its own draft-stop table and `--spec-min-p 0.3`.** (2026-10-18) Basalt's dense refit to Swift by KL + TV on 645 sampled transcripts: +3% drafts held per round offline, temp-1 decode ~+3%, greedy ~0-2% (follow texts priced at one ms-by-window-size table). A perfect draft stop would add only +11-13%, so more drafter work is not worth it; the next lever is the dense layers' GPU time.
- **`lct pull` turns on `HF_XET_HIGH_PERFORMANCE` unless the user set it.** (2026-10-18) The user wants the fastest download for any model; hf_xet's high-performance mode uses more connections and cores. Here it measured no gain only because the internet plan caps at ~19 MiB/s.
- **Flash-Next runs huihui-ai's abliterated v2 `swift-IQ3_XXS`, not SC117's or orcarouter's.** (2026-10-19) Same Swift 1.5 GSQ-RCO files with only quantized non-expert weights changed, so the pack, expert profile and drafter carry over (decode unchanged). Refused 0/10 borderline prompts vs 10/10; thinks up to ~9x longer on some how-to questions.
